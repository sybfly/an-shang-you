# 暗上游 · 乐龄牌桌

一个给亲友和老人玩的网页版暗牌扑克。三人起局，最多六人；每人扣下暗牌，只报牌型，再猜自己比前面的人大还是小。最先出完手牌的人成为「上游」，但牌局不结束——剩余玩家血战到底，最后留下的就是「下游」。

**当前版本 1.4.1：联机打牌、会按手数和牌型配牌的电脑、多局累计积分。**

## 现在能做什么

- 3～6 人同桌，按人数自动配牌：
  - 3 人：1 副牌，每人 18 张
  - 4 人：2 副牌，每人 27 张
  - 5 人：2 副牌，每人 21 张，余下 3 张开局亮明
  - 6 人：3 副牌，每人 27 张
- 完整牌型：单张、对子、三张、三带二、顺子、三连对、钢板、四张及以上同点数牌
- 暗牌扣牌、只报牌型、逐家猜大小
- 先手默认通过；猜错只收回自己的牌；前面某人判错后，后面与他的比较默认通过
- 下一轮由本轮实际出牌最大者先出，不论是否猜对；同点先出者先
- 同一轮多人出完，按本轮点数排先后
- 血战到底：有人出完后继续打，直到只剩最后一位；排出上游、名次和下游
- 每个人报的大小即时公开：座位上直接显示报的内容，并弹出公开提示
- 当前行动玩家的座位会变成醒目的红色，并带「轮到TA」标记
- 手牌像 JJ 斗地主一样叠放：牌与牌互相压住，只露出左上角，可以一屏看到更多牌
- 6 位房间号，房主浏览器就是牌桌，不设游戏服务器
- 掉线重连、原座位恢复
- 掉线玩家由房主「代过 / 代出最小单牌」
- 房主可加最多五位电脑牌友：会记公开牌、按手数配牌，同手数时优先三张/三连对/钢板/顺子，报大小前后一致并估算同点风险；同牌型已经到最大点数时不会再猜小
- 每局开局都按人数校验配牌：副数、手牌数、明牌数、总牌数不对就不开局
- 多局累计积分：每局按名次给分，结算页和「记分板」都能看，回大厅保留
- 大字牌面、三档文字大小、声音与语音提醒
- 手机、平板、电脑自适应
- 快捷打招呼、本轮记录、记分板、完整规则页

## 本地运行

浏览器不能直接双击 `index.html` 使用 ES Module，需要用一个静态文件服务打开。

### 方式一：Windows 双击

双击 `start-local.bat`，浏览器打开：

```
http://127.0.0.1:8080
```

### 方式二：Python

```bash
python -m http.server 8080 --bind 127.0.0.1
```

### 方式三：Node

```bash
node server.mjs
```

以上只是**本地静态文件服务**，不参与发牌、判定或牌局同步。

如果想让同一 Wi-Fi 下的手机访问电脑上的页面：

```bash
HOST=0.0.0.0 node server.mjs
```

然后在手机浏览器打开 `http://电脑局域网IP:8080`。这台电脑只负责发送静态文件，牌局仍然走浏览器之间的点对点连接。

如果亲友不在同一个 Wi-Fi，需要公网地址。临时试玩可以用 Cloudflare Quick Tunnel：

```bash
cloudflared tunnel --url http://127.0.0.1:8080
```

它会给出一个 `https://....trycloudflare.com` 地址。这个地址依赖本机和隧道进程，电脑休眠或进程关闭就失效；只适合临时试玩。长期使用请按下一节把 `dist/` 部署到静态托管。

### 三人试玩

在同一台电脑打开三个浏览器标签页（或三台设备），都访问同一个网址：

1. 第一个标签页填称呼，点「开一桌」，得到六位房间号
2. 第二个、第三个标签页点「加入牌桌」，输入房间号
3. 满三人后，房主点「开始这一局」

## 正式联网部署

这是纯静态站点：不需要编译或打包、没有 Node 后端、没有数据库。发布前先生成一个只含运行文件的目录：

```bash
node scripts/build-site.mjs
```

生成的 `dist/` 就是可直接上传的目录（约 10 个文件、300 KB）：

```
dist/
  index.html  styles.css  manifest.webmanifest  _headers  .nojekyll
  js/  vendor/  assets/
```

脚本会检查首页引用的本地文件是否齐全，并拒绝根路径引用（`/js/...` 这种写法在 GitHub Pages 子目录里会失效；本项目的引用都是相对的）。`tests/`、`server.mjs`、启动脚本不会进入 `dist/`。

### Cloudflare Pages

**最快：直接上传**

1. 登录 Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Upload assets**
2. 项目名随意填，把整个 `dist/` 文件夹拖进去
3. 发布后得到 `https://<项目名>.pages.dev`

**Git 自动部署**

仓库连到 Cloudflare Pages 后这样填：

| 配置项 | 值 |
| --- | --- |
| Build command | `node scripts/build-site.mjs` |
| Build output directory | `dist` |
| 环境变量 | 不需要 |

之后每次 push 自动重新发布。`_headers` 会为 HTML 设置 `no-cache`，并给 JS/CSS/图片加短缓存和基础安全响应头。

**命令行**

```bash
npx wrangler pages deploy dist --project-name an-shang-you
```

首次运行会打开浏览器登录 Cloudflare。

### GitHub Pages

先把仓库推到 GitHub，默认分支用 `main`。仓库里已带好 `.github/workflows/deploy-pages.yml`。

**推荐：GitHub Actions**

1. 打开仓库 **Settings → Pages → Build and deployment**
2. **Source** 选 **GitHub Actions**
3. push 到 `main`，或在 **Actions** 页手动运行 “Deploy to GitHub Pages”
4. 地址为 `https://<用户名>.github.io/<仓库名>/`

工作流会用 `node scripts/build-site.mjs` 生成 `dist/`，再整体发布。因为引用全是相对路径，放在 `/<仓库名>/` 子路径下也能正常打开。

**备选：直接发布分支**

Settings → Pages → Source 选 **Deploy from a branch**，分支 `main`、目录 `/(root)`。这样会把 `tests/`、`server.mjs` 一起公开（不影响使用），根目录的 `.nojekyll` 会跳过 Jekyll 处理。

### 上线前检查

- **必须 HTTPS**：WebRTC 需要安全上下文，`localhost` 除外。两个平台默认都带 HTTPS。
- **同一个网址**：所有牌友先打开同一个部署地址，再用六位房间号入座；不要一人用 `pages.dev`、一人用自定义域名。
- **牵线服务**：首次配对会访问 PeerJS 公共云 `0.peerjs.com`；公司网络或部分校园网拦截时，表现为“连接牵线服务超时”。
- **没有存档**：房主刷新或关掉标签页，这一桌就结束。
- **自定义域名**：Cloudflare Pages 在项目 **Custom domains** 里直接绑定；GitHub Pages 在 **Settings → Pages → Custom domain** 里填，并按提示配置 DNS。

Netlify、Vercel 静态站点或自己的 Nginx 也可以，把 `dist/` 的内容放到网站根目录即可。

## 「不设服务器」的边界

这个项目没有游戏服务器：

- 发牌、判定、轮次推进都在**房主浏览器**中完成
- 其他玩家只收到「自己的手牌 + 公共牌桌状态」，收不到别人的手牌
- 牌局数据点对点传输，不写入数据库

但 WebRTC 首次配对必须有「牵线」。当前使用 PeerJS 公共云服务做一次性牵线，它不参与牌局计算。如果要求完全零第三方，需要改成手动复制/粘贴 SDP 邀请码，体验会明显变差，暂未实现。

## 规则落地口径

规则来自《暗上游》原始设定，以下为实现时确认的口径：

| 项目 | 口径 |
| --- | --- |
| 跟牌 | 必须同牌型、同张数；不能跨牌型压制 |
| 过牌 | 任何时候都可以过；先手必须出第一手牌 |
| 猜大小 | 每位后手分别猜自己与前面每位已出牌者的大小；不能猜“相同” |
| 猜错 | 只收回猜错者自己的牌，其他人不受影响 |
| 判错连锁 | 前面某人已判错时，后面与他的比较默认通过 |
| 下一轮先手 | 本轮实际出牌最大且尚未出完者，不论是否猜对；同点先出者先；都已出完则按座位顺延 |
| 多人出完 | 比较本轮所出牌点数，大者排前；同点先出者排前 |
| 血战到底 | 有人出完后继续；最先出完是上游，最后留下是下游 |
| 报大小 | 报完即公开；座位上直接显示，所有人可见 |
| 连续牌 | A 可作 1 或 14，2 可参与 23456 等顺子；王不参与连续牌型 |
| 王 | 多副牌时，同种王可以组对子、三张、四张及以上；没有天王炸 |
| 四张及以上 | 普通牌型，不是炸弹，不能跨牌型压制 |
| 积分 | 每局按名次：第一名（人数-1）分，依次递减，最后一名 0 分；积分跨局累计，房主可在大厅清零 |

完整规则也可以在首页点「先看看完整规则」查看。


## 已知限制

- 房主离开或刷新，牌桌结束
- 六位房间号是入座口令，不是密码；不要用于陌生人竞技或敏感牌局
- 公共 PeerJS 牵线服务偶尔可能慢或在部分网络不可用
- 牌局没有服务端存档、没有观战、没有排行榜
- 电脑会按手数拆牌、同手数时优先多张/结构牌型，记住公开牌并估算同点风险，但不会算死牌，也不会和真人配合

## 隐私

- 不收集账号、手机号或身份信息
- 不写数据库
- 客人只收到自己的手牌；房主作为发牌和判定方，持有整桌牌局状态
- 语音提醒使用浏览器本地 `speechSynthesis`，不调用云端语音服务
